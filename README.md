# Sung Product Grammar v0.1

서비스를 통해 쌓아가는 제작자의 디자인 문법

작성일: 2026.10.06 · 업데이트: 2026.10.06 (타이포그래피 결정 반영) · 상태: 첫 기준안, 적용하면서 수정

## 1. 목적

앞으로 만드는 서비스들에 공통된 디자인 문법을 부여한다. 각 서비스는 독립적인 이름과 분위기를 가지되, 여러 작업을 접한 사람이 같은 제작자의 취향을 느낄 수 있도록 한다.

현재 가장 명확한 취향은 **미니멀한 스타일, 플랫한 UI, 서비스별 고유 액센트 컬러**이며, **마루 부리를 기본 폰트로 사용한다.** 이를 중심으로 시각적 기준을 정하고, 제품 구성과 인터랙션에 관한 원칙은 실제 서비스에 적용하면서 검증한다.

이 문서는 완성된 디자인 시스템이 아니다. 기본 폰트와 타이포그래피 시작값을 정하되, 모든 색상값·간격 수치·컴포넌트를 고정하지 않고 반복해서 사용할 판단 기준을 정리한 것이다.

## 2. 합의 수준

| 구분 | 내용 | 적용 방식 |
|---|---|---|
| 핵심 취향 | 미니멀한 스타일, 플랫한 UI, 서비스별 액센트 컬러 | 새로운 서비스의 기본 출발점 |
| 확정된 기본 폰트 | 마루 부리 | 새로운 서비스의 기본 폰트로 사용하되, 서비스 특성에 맞는 대체 서체 허용 |
| 타이포그래피 시작값 | 본문 18px·자간 0·행간 1.75 및 용도별 범위 | 서비스 특징과 화면에 따라 유연하게 조정 |
| 일부 공감한 원칙 | 한 문장으로 설명할 수 있는 아이디어, 추가 전에 덜어내기 | 방향으로 참고하되 절대 조건으로 삼지 않음 |
| 잠정 원칙 | 주요 행동의 위계, 타이포그래피 중심 구성, 의미 있는 모션, 제작자 서명 | 서비스에 적용해보고 자연스러운지 확인 |
| 미정 | 정확한 색상값·여백·모서리 수치, 서명 문구와 위치 | 필요할 때 결정 |

이하의 세부 규칙은 위 취향을 구현하기 위한 v0.1 기준안이다. 특정 비율이나 예외 없는 규칙으로 고정하지 않는다.

## 3. 시각적 문법

### 미니멀한 구성

사용자가 필요한 내용을 빠르게 이해하고 행동할 수 있도록 화면을 구성한다. 정보의 우선순위를 정하고, 장식과 중복 설명을 덜어낸다. 기능이 많아야 하는 서비스에서도 한 화면에 모든 요소를 같은 무게로 보여주지 않는다.

여백은 요소를 구분하고 중요한 내용을 드러내는 데 사용한다. 제목, 핵심 행동, 보조 정보가 자연스럽게 읽히는 순서를 만든다.

### 플랫한 UI

기본 UI는 단색 면, 선, 텍스트로 구성한다. 요소의 구분은 그림자나 입체 효과보다 배치, 여백, 크기, 대비로 해결한다.

- 그림자, 그라데이션, 반투명 효과는 기본 장식으로 사용하지 않는다.
- 테두리와 카드도 정보를 묶을 이유가 있을 때 사용한다.
- 모서리 형태는 서비스에 맞게 정하되, 한 서비스 안에서는 일관되게 유지한다.
- 버튼과 입력창은 평면적으로 표현하면서도 클릭·입력 가능 여부를 명확히 보여준다.

플랫한 UI 취향은 서비스의 모든 시각 표현을 평면으로 제한한다는 뜻은 아니다. One Wish Willow의 가지처럼 경험에 필요한 오브젝트, 질감, 입체 표현은 서비스 고유의 표현으로 둘 수 있다.

### 중립색 기반과 고유 액센트 컬러

검정, 흰색, 오프화이트, 회색을 기본 바탕으로 삼고, 서비스마다 대표 액센트 컬러 하나를 둔다. 밝은 화면과 어두운 화면은 서비스의 목적과 분위기에 따라 선택한다.

액센트 컬러는 핵심 행동, 선택 상태, 중요한 강조처럼 역할이 있는 곳에 사용한다. 모든 요소에 반복해서 쓰기보다 중립색과의 대비를 통해 존재감을 만든다. 동일 색상의 농도 변화는 허용한다.

오류·경고·성공을 나타내는 상태 색상과 콘텐츠 이미지의 색은 대표 액센트와 별도로 사용할 수 있다. 색만으로 상태를 전달하지 않고 텍스트나 형태를 함께 사용한다.

### 타이포그래피 중심

타이포그래피, 레이아웃, 색을 먼저 다듬고 장식은 필요한 경우에 더한다. 글자의 크기와 굵기, 줄 간격을 통해 정보의 위계를 만든다.

큰 타이포그래피는 핵심 문장이나 행동에 힘을 줄 때 사용한다. 모든 서비스에 거대한 제목을 의무적으로 넣지는 않는다. 기본 폰트는 **마루 부리**로 한다. 책처럼 차분하게 읽히는 인상과 앱·웹에서의 범용성을 함께 고려한 선택이다. 새로운 서비스는 마루 부리에서 시작하고, 한글·영문 가독성과 서비스의 분위기를 확인한다.

#### 기본 타이포그래피 설정

본문의 기본 시작값은 **18px / 자간 0 / 행간 1.75**다. 다음 수치는 앞서 제안한 웹용 기준이며, 특정 출판사의 조판값을 재현한 수치가 아니다.

| 용도 | 글자 크기 | 자간 (`letter-spacing`) | 행간 (`line-height`) |
|---|---:|---:|---:|
| 본문 | 17–18px (기본 18px) | 0부터 시작 | 1.7–1.8 (기본 1.75) |
| 짧은 소개·핵심 문장 | 20–24px | −0.01em–0 | 1.5–1.6 |
| 큰 제목 | 32–48px | −0.02em–0 | 1.2–1.3 |
| 버튼·설정·보조 UI | 14–16px | 0 | 1.4–1.5 |

**폰트 크기·자간·행간은 고정 규칙이 아니라 서비스 특징에 따라 유연하게 조정할 수 있는 시작값이다.** 콘텐츠 길이, 정보 밀도, 화면 크기, 사용자 행동과 서비스 분위기를 고려한다. 필요하면 위 범위 밖의 값도 사용할 수 있으며, 한 서비스 안에서 역할별 일관성을 유지한다.

행간은 글자 크기에 대한 줄 높이의 배율이다. 예를 들어 18px에 행간 1.75를 적용하면 줄 높이는 31.5px이다. 네이티브 앱에서는 px·CSS 값을 그대로 복사하지 않고 플랫폼의 글자 크기·줄 높이 설정과 사용자 글자 확대 기능에 맞춰 대응한다.

마루 부리를 버튼·설정에도 우선 검토하되, 작은 글자나 빠른 정보 판독이 중요한 화면에서는 고딕체를 보조 서체로 사용할 수 있다. 보조 고딕체의 종류는 아직 확정하지 않는다. 여백과 본문 폭 등 세부 조판값은 이번 결정에서 고정하지 않는다.

#### 서비스에 따른 대체 서체

다른 명조 계열도 서비스의 분위기에 따라 고려할 수 있다. 마루 부리보다 명조체의 인상이 강하게 느껴졌으므로 공통 기본값으로 지정하지 않고, 개별 서비스의 표현을 위한 후보로 남긴다.

- **SM3신신명조:** 고전적인 문학·책의 인상을 살리고 싶은 경우.
- **산돌 명조Neo1:** 책의 인상을 유지하면서 현대적인 표현을 검토하는 경우.
- **산돌 정체:** 단정한 본문 표현과 서비스에 맞는 글자 구조를 비교하는 경우.
- **본명조:** 정돈된 명조 표현을 검토하는 경우.

대체 서체를 선택할 때는 앱·웹 적용 조건과 필요한 문자 지원을 함께 확인한다. 마루 부리를 기본으로 정한 것이 기존 서비스의 폰트를 일괄 교체한다는 뜻은 아니다.

참고: [마루 부리 공식 소개](https://hangeul.naver.com/maruproject_11), [네이버 글꼴·라이선스 안내](https://hangeul.naver.com/font). 마루 부리를 앱에 포함할 때는 배포되는 라이선스 안내와 전문을 함께 포함한다.

## 4. 제품과 인터랙션의 문법

### 핵심 아이디어를 분명하게

서비스가 무엇을 제공하는지 한 문장으로 설명해본다. 이를 기능 수를 제한하는 규칙보다 핵심을 확인하는 질문으로 사용한다.

화면별로 사용자가 가장 먼저 해야 할 행동을 정하고 시각적 우선순위를 부여한다. 필요한 보조 행동과 설정은 제공하되, 핵심 행동과 같은 무게로 경쟁하지 않게 한다.

### 추가 전에 덜어내기

새로운 요소를 넣기 전에 현재 화면에서 제거하거나 합칠 수 있는 요소가 있는지 확인한다. 다만 이해에 필요한 설명, 오류 안내, 접근성에 필요한 단서는 유지한다. 간결함은 사용자가 추측해야 하는 상태를 만드는 근거가 될 수 없다.

### 행동에 맞는 반응

클릭, 저장, 제출 뒤에는 결과를 짧고 명확하게 보여준다. 단순한 성공 상태는 간결하게 알리고, 오류나 되돌릴 수 없는 행동에는 필요한 설명을 제공한다. 문구의 언어와 말투는 서비스에 맞춘다.

모션은 상태 변화, 진행, 행동의 결과를 이해하는 데 사용한다. 가지가 부러지는 장면처럼 경험 자체를 만드는 움직임은 적극적으로 활용할 수 있다. 모든 버튼과 카드에 장식적인 움직임을 넣지는 않는다.

### 기억에 남는 경험

서비스의 핵심 행동이나 결과가 기억에 남도록 설계한다. 고유 인터랙션은 잠정 원칙이며, 모든 서비스에 특별한 기믹을 추가할 의무는 없다. Workset처럼 핵심 기능의 빠르고 명확한 실행 자체가 인상이 될 수도 있다.

## 5. 공통 요소와 서비스별 자유

| 영역 | 공통으로 유지할 방향 | 서비스별로 선택할 요소 |
|---|---|---|
| 화면 구성 | 간결함, 명확한 위계, 목적이 있는 여백 | 화면 구조, 정보량, 탐색 방식 |
| 기본 UI | 플랫한 표현, 알아보기 쉬운 조작 요소 | 구체적인 형태와 크기 |
| 색 | 중립색 기반, 대표 액센트 컬러 | 액센트 색상, 밝고 어두운 테마 |
| 글자 | 마루 부리 기본, 읽기 쉬운 위계와 일관성 | 서비스에 맞는 대체·보조 서체, 크기·자간·행간, 제목의 표현 방식 |
| 반응 | 행동 결과를 분명하게 전달 | 모션, 사운드, 촉각 반응 |
| 분위기 | 불필요한 장식 절제 | 이미지, 질감, 세계관, 문장 톤 |

서비스 이름은 각각 유지하고, 제작자와 연결되는 작은 서명을 공통으로 사용하는 방향을 검토한다. 후보는 `by Sung`, `made by sungdotio`이며, 문구와 위치는 아직 확정하지 않는다. 서명은 핵심 경험을 방해하지 않는 곳에 둔다.

## 6. 현재 서비스에 대입하기

아래는 적용 방향의 예시이며, 기존 서비스를 즉시 수정하기로 결정한 것은 아니다.

| 서비스 | 공통 문법을 적용할 부분 | 고유하게 유지할 부분 |
|---|---|---|
| Workset | 타이포그래피 중심 구성, 주요 실행 행동 강조, 간결한 설정 UI | 작업 탭을 빠르게 여는 경험 |
| One Wish Willow | 입력·피드·관리 UI의 플랫한 표현, 명확한 정보 위계 | 어두운 분위기, 가지 오브젝트, 부러뜨리는 장면과 소리 |
| My Live | 결과물의 정보 위계, 여백, 고유 액센트 | Receipt/Stats 표현 방향과 공연 콘텐츠 |

## 7. 적용과 업데이트

새 서비스를 시작할 때 핵심 아이디어, 첫 화면의 주요 행동, 액센트 컬러, 서비스별 표현을 먼저 정한다. 폰트는 마루 부리를 기본으로 시작하고, 타이포그래피 시작값을 서비스에 맞춰 조정한다. 화면을 검토할 때는 다음 질문을 사용한다.

1. 사용자가 무엇을 하는 서비스인지, 어디서 시작해야 하는지 알 수 있는가?
2. 타이포그래피와 여백만으로도 정보의 위계가 보이는가?
3. 장식과 UI 요소 각각에 역할이 있는가?
4. 액센트 컬러가 일관된 역할을 가지는가?
5. 플랫한 표현에서도 조작 가능 여부와 상태 변화가 명확한가?
6. 공통 문법이 서비스 고유의 경험을 잘 지원하는가?

여러 서비스에서 반복해 유효했던 규칙은 유지하고, 잘 맞지 않았던 규칙은 수정한다. 그 과정에서 반복되는 색·간격·타이포 수치가 생기면 디자인 토큰으로, 반복되는 UI가 생기면 공통 컴포넌트로 발전시킨다.

**공통 CSS 토큰, 컴포넌트, 스타터 템플릿을 만드는 개발 프로젝트로 구체화되면 Claude로 넘길 것.** 현재는 디자인 방향과 판단 기준을 정리하는 단계다.
